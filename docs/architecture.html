System Architecture

Factory Inventory Management System

A full-stack demo: a Vue 3 single-page application backed by a Python FastAPI service. All data is served from in-memory JSON fixtures — there is no database. Built for filtering, dashboards, and operational reporting across warehouses and product categories.

Overview

Three-Layer Architecture

A clean separation between presentation, API, and data. The browser renders Vue components; FastAPI exposes a REST API; JSON files are loaded once into memory at startup.

Request Lifecycle

Data Flow

How a filter selection becomes rendered data — the same path every view follows.

1
User action
A view mounts or the FilterBar changes (period, warehouse, category, status).
2
Collect filters
useFilters singleton refs → getCurrentFilters() builds the params object.
3
API call
api.js serializes params and issues an Axios GET to :8001/api/….
4
Filter in memory
FastAPI runs apply_filters / filter_by_month over the loaded lists.
5
Validate
Pydantic response_model validates & serializes the result to JSON.
6
Render
Response lands in a Vue ref; computed props derive and the template renders.

Conventions

Key Patterns

Shared filter state

Four global filters (Time Period, Warehouse, Category, Order Status) live in a singleton useFilters composable and apply across every view via query params.

Reactivity model

Raw API data is held in refs; all derived values (totals, chart series, filtered lists) are computed — cached until dependencies change.

Stateless backend

All filtering happens in Python over copies of in-memory lists — original data is never mutated. Restarting the server reloads fixtures from disk.

Typed contracts

Every GET response is shaped by a Pydantic response_model, so JSON structure changes must be mirrored in both the model and the fixture file.
